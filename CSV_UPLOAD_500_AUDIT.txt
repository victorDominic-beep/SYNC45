3. CSV VALIDATION PATH
======================

The updated CSV mappings are present in:

src/connectors/ledger/excel/ExcelConnector.ts

Mappings:

- transactionReference maps to reference
- senderName maps to customer
- transactionDate maps to paidAt
- amount maps to amount
- status maps to status
- currency is optional
- missing currency defaults to NGN
- user is ignored

The validation path also uses these mappings.

The required columns are calculated as all canonical columns except currency.

A CSV with this header should pass validation:

transactionReference,amount,status,transactionDate,senderName
TRF_TEST_001,5000,SUCCESS,2026-09-01,Customer Name

The absence of currency should not cause a validation failure in the current source.


4. MOST LIKELY CODE-LEVEL FAILURE CAUSES
=========================================

Because the organization's format is supported by the current source, the most likely causes are infrastructure or request-shape issues.

A. Render cannot write to ./data

Multer writes to:

./data

If that directory does not exist in the deployed working directory, or is not writable, Multer can throw an ENOENT or permission-related exception before the controller executes.

B. Multipart field name is wrong

The backend requires:

file

If the frontend sends another field name, Multer can throw:

MulterError: Unexpected field

C. The deployed Render build is stale

The current source supports:

- transactionReference
- senderName
- missing currency
- NGN default

If Render is running an older deployment, it may still reject the CSV for missing:

- reference
- currency
- customer

D. The file contains formatting or data issues

The current validator rejects a row if:

- transactionReference/reference is empty
- amount is missing or not numeric
- status is empty
- senderName/customer is empty
- transactionDate/paidAt is empty

E. File-size or extension rejection

Files over 5 MB or extensions other than .csv, .xlsx, or .xls can fail in Multer before the controller.
